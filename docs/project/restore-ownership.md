## Exited associated-shell accounting v3 (offline candidate)

The new family is separate from both earlier dispositions. It accepts only an exact ten-record
shell history and original seven-field protected-dimension failure witness; current diagnostic
receipts remain excluded without conversion. Historical accounting does not restore the application,
certify preservation or establish exit time/descendant/session closure.

Its current proof uses one per-reply-authenticated persistent socket, continuing peer inventory
matching, held live generations and active namespace/procfs checks, current ELF measurement, and
exact primitive ESRCH for the old PID. Every current window is protected; proposal, approval and
apply independently prove their own callers. No numeric controller-set or generic lookup-failure
shortcut supplies ownership. New live proofs establish genuine self coordinates without any init
namespace access, retaining authenticated proc components. The sole live method is procfs-self
`.v2`; the init and procfs-self `.v1` methods remain immutable historical testimony. Caller, peer and
protected owners form a frozen full cohort before ancestry discovery; their held pidfds refresh
active PID/user namespaces. Other ancestors have distinct exclusion-only generations: genuine
singleton PID vectors, held-directory identity, four UIDs, stable boot/start/parent and pidfd
liveness, without user-namespace/executable claims or target namespace ioctls. Failed full proofs
never weaken; weak-to-full requests and late role changes refuse without promotion. Every row
remains checked at both late vetoes. Shared managers confer no ownership of other sessions.
The checked profile is stable upstream-compatible Linux >=7.2.6, little-endian x86_64 GNU LP64.
Unsupported interfaces/ABI or unproved scope still refuse. Old-method completions retain historical
replay; unfinished old-method work cannot obtain new live authority. Guarded ELF lookups detect
sampled drift, not every transient privileged substitution; readonly opens are not a sandbox.

Historical native-serving/PID-coordinate continuity is explicit platform trust, separately
acknowledged per plan, not executable attestation. Captured CLI-version objects remain unchanged;
the compositor member alone is compared to authenticated direct Version. Staging precedes consume,
with exact future bytes, fresh semantic barriers and live/expiry vetoes after final capacity and
before publication. Replay is historical only. See [architecture](../architecture.md#exited-associated-shell-v3-offline-candidate)
and [operator limits](../usage.md#exited-associated-shell-disposition-v3-offline-candidate).

## Association-coherence correction (offline candidate)

### Capture selection for future qualification

The existing CLI now accepts repeatable `capture --window-id INT`. It selects exact IDs from the
same genuine read-only capture, preserving source order, every selected recipe including extras,
and all supporting topology/identity/process observations. Negative/noninteger, duplicate and absent
IDs refuse before artifact/pointer commit. No flag preserves full-capture behavior. The small closed
generated `capture_selection` object records `kind="window-ids"`, sorted `window_ids` and
`observed_window_count` in the selected snapshot and result, bound by its ordinary immutable digest.
It is selection provenance, not a full-desktop claim or a reference to an unpersisted source artifact.
Readiness is recomputed without changing source coherence; no model or restore ownership/history
semantics change. The snapshot uses ordinary Store pointers, not a new partial-state mechanism.

This is **not selective probing**: whole-desktop/process/session metadata is still read, including
potential Claude transcript-title reads before redaction; supporting unselected process observations
remain saved. It is not resource isolation. A private `--state-root` keeps qualification artifacts
separate from login captures but never bypasses canonical compositor exclusion/history on apply.
No generated snapshots or receipts may be edited to create qualification inputs.

A one-window selection can still contain multiple launch recipes. Future preflight must inspect the
actual saved selected snapshot and immutable existing `restore` dry-run receipt, require exactly one
planned entry and no extras, and independently review a harmless admitted recipe plus destination,
protected baseline and idle interval. Dry-run does not certify executable admission or grant approval.
Use exact saved snapshot/receipt digests, then stop for separate explicit apply approval. Do not
silently discard recipes, introduce another launcher, clear fences or retry ambiguous effects.

## Review corrections and proof limits

Desired host environment is constructed from the bootstrap's raw initial environment on both sides
of the prepare exchange. Post-exec proof compares the host's **raw** `/proc/PID/environ` observation
against that desired map; wrong backend or extra socket/service-control variables are refused.
This observes the kernel-exposed initial environment region, which a process can rewrite. It is not
an observation of the host's current dynamic libc/Python environment or proof that it never changed.

JSON decoding rejects both nonfinite constants and overflow through ordinary float syntax at any
nesting depth. Executable descriptors open nonblocking before fstat admission, so a FIFO without a
writer is promptly rejected. Absolute deadline checks surround image hashing and its chunks. These
checks do not promise interruption of every filesystem/kernel syscall or a hard wall-clock bound
against hung storage; no timeout kills or automatic cleanup were added.

Peer credentials, pidfds and binary pins constrain the observed process and exchange. They do not
authenticate Python module origin merely because its interpreter image matches. Installed bootstrap,
interpreter/import environment and coordinator code are trusted. The nonce is an attempt binding,
not a privilege secret or protection against a malicious same-UID process that can inspect the
bootstrap command line. There is no new account-owner sandbox or general process authentication.

## Why

A new window and matching application label are observations, not launch provenance. A spawn
acknowledgement is not a process receipt. Singleton applications may forward to existing hosts,
restore several windows or map late. Timeouts cannot authorize a second launch or cleanup.
The current different-label fallback and matching-label acceptance are independently unsafe.

## Bounded first capability

Support fresh native Ghostty hosts for shell, command, declared, Pi and Claude recipes. Keep
ordinary restore's CLI and per-compositor writer exclusion. No private recovery adapter, daemon,
service changes, process termination, or general launcher framework. Other applications remain
explicit unsupported ownership cases until their launch behavior is qualified; this is not
universal desktop restoration. Capture/preview remain effect-free.

Use a short-lived public Python bootstrap launched through Niri, rather than spawning a terminal
as a child of the restore service. Direct Popen from the oneshot service would inherit its cgroup;
setsid does not detach cgroup membership. Niri retains control of launch environment/session scope.

The trusted bootstrap must validate a bounded, one-use handshake with the trusted coordinator before
executing one admitted host. This is not authentication against a malicious same UID. Bind the
attempt, peer credentials, process start identity and executable;
retain a Linux pidfd before granting the exec transition. Same-process descriptor exec is mandatory;
there is no child fallback or unobserved descendant transition. Close control descriptors before the
application runs; do not inherit writer locks into the application. Disconnect, timeout or partial
handshake never triggers an automatic second bootstrap or host. No kill-on-error behavior.

Construct a controlled fresh-host argv rather than preserve arbitrary captured Ghostty host flags.
Keep the explicit command after `-e` and the saved working directory. Force native Wayland and
non-single-instance behavior. Reject remote actions, wrappers and unsupported host options instead
of silently changing their semantics. Preserve required user command environment; remove stale
inherited Wayland socket descriptors and service/control variables. Do not read private profiles
while developing or testing. Any loss of custom host configuration must be explicitly documented.

Before window placement, require a continuously live launch-bound process identity, the expected
running executable, a fresh native window associated with that process, and no protected host or
window overlap. Revalidate before subsequent effects. No label/title, elapsed time, unique candidate,
or newly observed PID is a substitute for provenance. All process/window observations are bounded.

This relies on the explicitly trusted native Ghostty client creating its own Wayland connection
without forwarding, forking or transferring that connection. Niri reports connection-creator PID,
not a connection-generation token. It cannot generally prove ownership for arbitrary clients or
stale inherited/transferred connections. State these assumptions; do not market a universal PID proof.
Native validation of the supported Ghostty behavior remains a separate approval gate.

## Accounting and layout

Persist intent before every potentially effectful launch or placement phase. Retain unresolved
intent across coordinator crashes, scoped to compositor identity independently of caller Store root.
Do not allow another snapshot or another Store root to evade unresolved-effect protection. A new
compositor is a separate identity; surviving processes must still be protected on observation.
Failure to persist before dispatch means no dispatch. Failure after dispatch stays ambiguous.

Separate dispatch, ownership, placement observation and native session resumption in receipts.
Terminal launch/placement never proves a resumed session is usable. Account for every observed
owned output, including surplus. No full-success status or success pointer for partial/ambiguous
results. Unsupported entries and unprocessed entries remain visible. Unknown windows remain untouched.
Late windows after the bounded observation interval cannot be claimed absent indefinitely.

For any future admitted self-restoring transport, group by exact launch semantics (including cwd
and profile-bearing argv), dispatch once per group, and retain missing/surplus outcomes. Never use
missing-window timeouts as launch permission. Fake browser tests prove accounting only, not a native
browser ownership producer.

Preserve supported column/floating reconstruction rather than quietly removing it to pass tests.
Revalidate owned windows, column membership and focus around focus-dependent actions. Existing Niri
focus/action operations are not atomic against user input; report that limitation and require an
idle desktop for qualification. Do not claim race-free protection from preflight polling alone.
If ownership cannot be carried safely into a specific layout action, stop with explicit partial
status and retain the design gap; do not call a workspace-only reduction complete reconstruction.

## Historical integration decision (implemented and reviewed offline)

Use one in-memory restore-attempt owner to hold the compositor flock through all subordinate
launches, window associations, layout observations and terminal recording. A launch consumes one
bound ticket and never reacquires or bypasses that lock. Retain existing standalone producer tests
as lower-level evidence, but use one shared admission/journaling implementation rather than two
independent paths. Reject closed, poisoned or mismatched attempt capabilities.

Canonical append-only attempt records must be independent of caller Store roots. Each attempt
binds its original Store identity, source snapshot, complete frozen plan and prepared receipt;
each launch/layout step records durable intent before dispatch. All legacy, orphan, malformed or
incomplete histories block effects. No automatic retry, rollback, timeout settlement or marker
removal. Read-only inspection remains serialized and available. A verified terminal record may
release future effect admission without erasing history; do not leave unrelated continuity writers
permanently disabled after successful restoration. Exact completed-source replay returns retained
historical accounting without effects and without claiming fresh native verification. Another
source cannot bypass any unresolved attempt. Do not impose a blanket one-launch or one-restore
lifetime cap as a shortcut around proper attempt ownership.

Terminal order is complete bounded observation, durable final receipt, durable canonical terminal,
then original-Store success pointer as a projection. A receipt without its terminal is unresolved.
A missing pointer after a committed terminal is not permission to repeat effects. Invalid terminal
references never confer admission. No partial/ambiguous result updates the success pointer. A
fully accounted outcome containing unsupported entries is distinct from an indeterminate effect;
its exact non-success semantics must be validated rather than inferred from a status prefix.

For the first integrated producer, admit only the controlled fresh native Ghostty contract. Other
application kinds must be reported as unsupported before any launch. Browser no-launch cases are
not evidence of working browser restore. A successfully arranged multi-host Ghostty example is
required alongside refusal cases. Surplus or ambiguous outputs stop further effects; every plan
entry and observed owned output remains accounted for. Process evidence becomes a bounded native
window association only under the documented trusted-client assumptions, not a general PID proof.

Layout must use fresh owned/protected cohorts rather than assuming protected columns are already
a prefix. The useful supported algorithm moves owned singleton columns to an ordered suffix,
consumes only the exact owned singleton at the immediate right of the owned seed, then sizes the
assembled column. Preserve protected grouping, relative order, sizes and workspace membership;
numeric column reindexing from owned insertion/removal is not an explicit protected-window move.
Account for every workspace/window focus change and naming action. No final-focus cleanup after
ambiguity. Bind destinations to unambiguous current workspace/output identities rather than a
global index map. Width is window geometry plus decorations, not blindly the saved tile width.
Floating coordinates require a correct absolute/relative conversion; negative CLI numbers are
relative adjustments. Reobserve expected transitions without redispatch; do not certify an action
log as resulting geometry. The preflight/action focus race remains non-atomic and explicitly limited.

fixed i32 tokens. [`scrolling.rs` 4990–5042](https://github.com/YaLTeR/niri/blob/62c230a662ac913a54fc49c86fda0406da3f3ba9/src/layout/scrolling.rs#L4990-L5042)
adds decorations for the active window and clamps the tile to 1–100000. [`tile.rs` 938–984](https://github.com/YaLTeR/niri/blob/62c230a662ac913a54fc49c86fda0406da3f3ba9/src/layout/tile.rs#L938-L984)
subtracts the border then floors the integer Wayland request; an inverse just below an integer can
lose a pixel. Admission checks both exact reconstruction and this inverse floor, without tolerances.
Measured decoration is not a full native-state model: [`tile.rs` 803–845](https://github.com/YaLTeR/niri/blob/62c230a662ac913a54fc49c86fda0406da3f3ba9/src/layout/tile.rs#L803-L845)
quantizes window size before adding borders, and native client min/max constraints also apply.
Unobserved residue/constraints may still fail exact postconditions. No native success is inferred.
Old invalid CLI intents remain blocked; this correction does not inspect or rewrite their artifacts.

Floating quantization also follows the same revision's `src/layout/floating.rs` 338–348: IPC rounds
logical offsets to physical pixels, then converts back to logical coordinates. `src/utils/mod.rs`
208–228 emits `LogicalOutput.scale` from `output.current_scale().fractional_scale()`; the public
`niri-ipc/src/lib.rs` 1210–1271 exposes it under `Output.logical.scale`. Rust `f64::round` uses ties
away from zero, not Python's ties-to-even. The candidate binds that observed scale and compares exact
observable coordinates, without tolerances; dispatch uses 17-digit round-trip signed deltas toward
the quantized target. `floating.rs` 964–1011 still adjusts an unrounded internal position, so hidden
residue/native constraints can fail strict post-observation. This is not exact internal-position
recovery, nor permission to retry. Saved tile height is not restored.
