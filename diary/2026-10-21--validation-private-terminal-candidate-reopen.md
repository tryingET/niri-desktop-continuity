# Native single-shell candidate reopen

A privately staged Ghostty candidate was first opened through Niri, then captured
with the installed continuity CLI into a separate private Store. The immutable
selected snapshot contained exactly one shell recipe and no extra-tab recipes.
The operator inspected and approved the exact dry-run before apply.

Observed apply returned exit zero and `reopened`, with one newly associated host,
recorded column placement, original-focus restoration and a terminal canonical
history. All protected window rows matched the admitted baseline. Requested
width was already present: this proves observed width preservation, not execution
of the resize action. The success pointer referenced the original captured source.

An independent read-only inspection checked content-addressed artifacts, history
links, recipe/bootstrap/cwd agreement, protected geometry and recorded effects.
No discrepancy was found within that evidence. It did not invoke the product,
rerun native effects or establish universal absence of other process effects.

The private host separately showed native GPU-backed rendering. Human acceptance
of typing, output, clipboard, appearance and resize was obtained for a subsequent
normal-profile instance of the same binary. This does not rewrite the restore
receipt's `native_session: not-proved`, prove agent conversation recovery, or make
controlled restore preserve custom configuration that it intentionally discards.

No source modification, fence deletion, historical-attempt rewrite, retry,
automatic process cleanup, existing-terminal restart, login deployment or full
restore was performed. The installed runtime was isolated from the dirty checkout.
Private snapshot, process identities, paths and native logs remain outside Git.
This bounded success does not settle earlier interrupted attempts or qualify all
layout/association/width branches, reboot/login behavior or a public release.
