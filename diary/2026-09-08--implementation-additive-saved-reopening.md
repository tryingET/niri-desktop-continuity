# Additive saved-set reopening

The portable coordinator now has an explicit `--mode additive --saved-set <digest>` branch on
its existing plan/preview/approve/reconstruct/verify/inspect lifecycle. Its distinct
`desktop-continuity.saved-reopen.v1` schema preserves frozen replacement v1/v2 contracts.
No former live window or PID is invented to select a saved conversation. All current windows
are protected; the owner privately resolves exact native identities and partitions selected refs
into missing, already-present and unresolved sets. Unresolved refs block the exact plan.

The coordinator grants only one launch permit per admitted missing ref and then one exact
admitted-focus restoration. Shutdown, service, layout, already-present launches, repeated refs
and unknown targets are refused before dispatch. Already-present-only execution consumes the
canonical approval with zero effects, rather than faking a launch or destructive proof.
Canonical history independently verifies the target set and contiguous event order.

Native file/cwd/runtime/bootstrap/surface/window predicates and ownership/images/focus/protected
preservation remain mandatory. For present refs these concern the current observed native process,
not a fictitious newly launched process. Old-tree exit, services, labels/holds and exact geometry
are not additive proof dimensions. Normal tiling insertion may change geometry. No tab targeting,
process-memory/draft/scrollback recovery, provider usability or human acceptance is claimed.

Source/profile pins, fresh observation, exact loss acceptance, expiry, shared compositor exclusion,
canonical prepare/consume/ready, cross-root replay fencing and non-upgrading interrupted history
are reused unchanged. There is no machine adapter, private recipe, native transcript, real session
identity or new runtime dependency in the public package. The separate machine incident recovery
is not evidence that this new integrated mode has native qualification.

## Validation

A handwritten fabricated endpoint and portable regressions exercise zero old-process selection,
missing/present/mixed sets, destructive/ref/order refusals, mandatory native predicates, unresolved
coverage, drift/expiry/focus, disconnect, canonical event consistency and replay. A separate test
builds and installs the wheel outside the checkout and drives the actual console script through
missing-ref and zero-effect present-only lifecycles. Only fabricated capture/profile/lock providers
are replaced; the endpoint uses actual subprocess socket IPC and no native effect transport.

The initial complete `UV_OFFLINE=1 just ci` passed 386 tests, privacy/source checks, package builds
and legacy v1/v2 installed-wheel smoke. Thirteen subsequent hardening regressions passed, including
strict null selectors, mixed-ref launch exclusion, per-effect expiry, canonical target/order checks,
and rejection of invented destructive proof. The final combined `UV_OFFLINE=1 just ci` passed
399 tests, Python 3.11/source/privacy checks, sdist/wheel builds and installed legacy v1/v2 smoke.
The test total includes both actual installed-console additive workflows. `git diff --check` also
passed. These observations do not substitute for independent source review, owner machine testing,
private profile provisioning or explicitly approved live integration proof.

## Independent-review usability corrections

Independent source review found no safety blocker, but identified two correctness gaps. Additive
HTML preview now shows the exact saved-set digest and full missing/present/unresolved ref ledger
with counts, instead of relying on empty live-window selection and an unchanged topology map.
It explicitly distinguishes a no-launch plan from reopening missing refs. Observed values remain
HTML/XML escaped; private manifests/native bodies are not rendered. The existing surveyor-ledger
tokens/classes are unchanged. `DESIGN.md` lint had zero errors and one pre-existing orphan-token
warning; agent-context and CSS exports informed the change. No design-token patch was needed.

Explicit empty `--app-id` and `--version` arguments now refuse like other additive live selectors,
instead of being silently dropped by a truthiness test. Handwritten CLI regressions cover both;
preview cases cover missing/no-op/unresolved scope, escaped malicious display data, hidden private
data and unchanged style bytes. The focused follow-up passed 48 tests. The corrected combined
`UV_OFFLINE=1 just ci` then passed 406 tests, source/privacy checks, package builds and installed
v1/v2 console smoke; the total includes both installed additive workflows. `git diff --check`
passed. No live effects or native qualification follow from these tests.
